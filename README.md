# Detour Proxy

> 把浏览器流量「绕道」经你局域网内的 v2raya 代理端点转发。

一款基于 **Manifest V3** 的浏览器代理扩展（**Detour Proxy**），适用于 **Google Chrome** 和 **Microsoft Edge**。它通过 Chromium 的代理配置接口（`chrome.proxy`）配置浏览器的代理行为，把浏览器流量转发到你局域网（LAN）内已经部署好的 **v2raya** 代理端点。

> 该扩展**不会**运行、安装或管理 v2raya 服务本身。它只负责配置、启用、禁用并报告浏览器的代理行为。v2raya 需要你自行在 LAN 内的某台机器上部署并运行。

## 功能特性

- **四种代理模式**：直连（Direct）、系统代理（System）、固定服务器（Fixed_Servers）、自动配置脚本（PAC）。
- **快速开关**：弹窗内一键启用/禁用代理；禁用时回到直连，但保留你的配置。
- **代理端点配置**：主机、端口、协议（SOCKS5 / SOCKS4 / HTTP / HTTPS）。
- **绕过列表**：指定无需走代理、直接连接的主机（例如本地与 LAN 资源）。
- **PAC 脚本支持**：支持「远程 URL」或「内联脚本」两种来源指定 PAC 自动配置脚本。
- **状态报告**：实时显示当前模式、端点 / PAC 来源，以及工具栏指示。
- **错误提示**：端点不可达或配置应用失败时给出明确反馈。
- **跨会话持久化**：重启浏览器后自动恢复上次的代理模式。
- **无障碍与响应式 UI**：键盘可达、带可见标签，跟随系统浅色 / 深色主题。
- **Chrome / Edge 一致体验**：同一份配置在两个浏览器上行为一致。

## 工作原理

```
┌─────────────┐     配置/启用/禁用      ┌──────────────────┐     转发流量     ┌──────────────────┐
│  你（用户）  │ ───────────────────▶ │  本扩展（浏览器） │ ─────────────▶ │ LAN 内 v2raya 端点 │
└─────────────┘                       └──────────────────┘                 └──────────────────┘
                                       通过 chrome.proxy API                  你自行部署运行
```

你在扩展中填入 v2raya 暴露的代理主机、端口和协议，扩展通过 Chromium 代理接口把这些设置应用到浏览器，从而让浏览器流量经由 v2raya 转发。

## 环境要求

- **Node.js** ≥ 18（用于构建，依赖 `node:fs/promises` 等内置模块）
- **npm**（随 Node.js 一起安装）
- **Google Chrome** 或 **Microsoft Edge**（基于 Chromium，支持 Manifest V3）
- 一个**已经在 LAN 内运行的 v2raya 代理端点**（扩展只负责连接，不负责部署）

## 构建与打包

源代码使用 TypeScript 编写，需要先编译并组装成浏览器可加载的目录。

```bash
# 1. 安装依赖
npm install

# 2. 编译 + 组装可加载的扩展目录（输出到 ./extension）
npm run package
```

`npm run package` 会做两件事：

1. `tsc` 将 `src/**` 编译到 `dist/src/**`（保留目录结构与 ES 模块相对导入）。
2. `scripts/package.mjs` 把编译产物、各页面的 HTML/CSS 以及共享的 `theme.css` 组装到 `./extension`，并生成路径正确的 `manifest.json`。

组装后的 `extension/` 结构如下：

```
extension/
├── manifest.json              # service_worker / popup / options 路径均已修正
├── icons/                     # 工具栏 / 商店图标（16/32/48/128 PNG）
├── background/                # 后台 Service Worker（index.js 等）
├── core/                      # 共享核心逻辑（校验、序列化、状态等）
├── ui/                        # popup 与 options 共享的消息层与 DOM 工具
├── popup/
│   ├── popup.html  popup.css  popup.js  theme.css
└── options/
    ├── options.html options.css options.js theme.css
```

> 图标由 `npm run icons`（`scripts/icons.mjs`，基于 sharp）从 `branding/detour-icon.svg` 渲染为多档 PNG，`npm run package` 会自动先生成再拷入 `extension/icons/`。

> 只想编译、不想组装时，可单独运行 `npm run build`。但注意：`dist/` 下的产物**不能**直接加载到浏览器，必须用 `npm run package` 生成 `extension/` 才能加载。

## 安装到浏览器

扩展以**未打包（unpacked）**形式加载，便于本地测试。

### Chrome

1. 地址栏打开 `chrome://extensions`
2. 打开右上角的 **开发者模式 / Developer mode**
3. 点击 **加载已解压的扩展程序 / Load unpacked**
4. 选择项目下的 `extension` 文件夹（例如 `e:\Work\GitHub\iProxy\extension`）

### Edge

1. 地址栏打开 `edge://extensions`
2. 打开左下角的 **开发人员模式**
3. 点击 **加载解压缩的扩展**
4. 选择同一个 `extension` 文件夹

### 更新扩展

修改代码后，重新运行 `npm run package`，然后回到扩展管理页点击该扩展的**刷新 / 重新加载**按钮即可。

## 使用说明

扩展的界面分为两部分：**弹窗界面**用于日常快速操作，**设置页面**用于详细配置。

### 弹窗界面（快速操作）

点击浏览器工具栏上的扩展图标（🛡️）打开弹窗，包含：

- **状态卡片**：状态指示点 + 文案（如「已禁用」），以及**启用/禁用主开关**。开关关闭时浏览器回到直连，但不会清除你的配置；再次打开时会恢复到你上次选择的转发模式。
- **状态列表**：显示当前模式；固定服务器模式下显示代理端点（主机:端口 / 协议），PAC 模式下显示 PAC 来源（远程 URL 显示地址、内联脚本显示「内联脚本」，标签随来源切换）。
- **代理模式快速切换**：在三种**转发模式**间选择——系统代理 / 固定服务器 / PAC。模式选择器只决定「用哪个模式」，**主开关才是实时开/关的唯一入口**：
  - 代理**已启用**时选模式 → 立即实时切换到该模式。
  - 代理**未启用**时选模式 → 仅记录为「待启用模式」，代理保持关闭，待你打开主开关时再生效。
  - 高亮有两种：**实心填充**表示「当前正在路由的生效模式」（启用时）；**描边高亮**表示「已选中、待启用的模式」（禁用时）——一眼即可区分代理是否已开启。直连不在这里选择，而是通过关闭主开关达成。
- **设置入口**：右上角 ⚙️ 图标，以及底部「高级设置（端点 / 绕过列表 / PAC）」按钮，点击打开设置页面。

### 设置页面（详细配置）

通过弹窗的设置入口打开（在新标签页中显示），用于配置以下三块内容，每块都有独立的保存按钮和就近的校验/反馈提示。**这三块的「保存」都只持久化配置、不会切换实时代理**——实际启用与模式切换一律在弹窗里完成：

1. **代理端点**：主机地址、端口、协议。
2. **绕过列表**：每行一个主机模式，匹配的主机直接连接、不走代理。
3. **PAC 脚本**：可选「远程 URL」或「内联脚本」两种来源。保存后到弹窗切换到「PAC」模式即可生效。

### 代理模式说明

代理模式分为「转发模式」和「直连」两类。**转发模式**（系统代理 / 固定服务器 / PAC）在弹窗的模式选择器里选择；**直连**通过关闭启用开关达成，而不是作为一个模式去选。

| 模式 | 含义 | 如何启用 | 前置条件 |
| --- | --- | --- | --- |
| **直连（Direct）** | 不经任何代理直接联网 | 关闭启用开关 | 无 |
| **系统代理（System）** | 使用操作系统的代理设置 | 模式选择器选中 + 开关开启 | 无 |
| **固定服务器（Fixed_Servers）** | 通过你配置的 v2raya 端点转发，并应用绕过列表 | 模式选择器选中 + 开关开启 | 必须已保存**有效的代理端点** |
| **PAC** | 使用指定的 PAC 脚本（远程 URL 或内联脚本）决定如何代理 | 模式选择器选中 + 开关开启 | 必须已保存**有效的 PAC 来源**（URL 或内联脚本） |

> 选择器里选中的转发模式会被记住（Selected_Mode）。关闭开关回到直连后，再次打开开关会**恢复到你上次选择的转发模式**，而不是固定跳到某一个。
>
> 未启用时点选某个模式只是把它记为「待启用模式」，不会立即生效；前置条件（有效端点 / PAC 来源）会在你打开主开关时才检查。
>
> 已启用时若切换到尚未满足前置条件的固定服务器或 PAC，扩展会**拒绝切换**、保留原模式，并提示你先去设置中完成配置。

### 字段与校验规则

| 字段 | 规则 |
| --- | --- |
| **主机地址 (host)** | 必填，长度 1–253 个字符 |
| **端口 (port)** | 必填，1–65535 之间的整数（不接受空、非数字、小数） |
| **协议 (protocol)** | 必须为 `SOCKS5`、`SOCKS4`、`HTTP`、`HTTPS` 之一 |
| **PAC URL**（远程 URL 来源） | 长度 1–2048 个字符 |
| **PAC 内联脚本**（内联来源） | 长度 1–100000 个字符 |
| **绕过列表 (bypass list)** | 最多 100 条；每条 1–255 个字符；不允许空条目 |

绕过列表的**默认值**为 `localhost` 和 `127.0.0.1`：当从未配置过绕过列表，或提交了空列表时，扩展会自动应用这份默认列表。

## 典型使用流程

1. 确认 LAN 内的 v2raya 已经运行，并记下它暴露的**主机、端口、协议**（例如 `192.168.1.10:1080`，SOCKS5）。
2. 打开扩展弹窗 → 点击 ⚙️ 或底部按钮进入**设置页面**。
3. 在「代理端点」填入主机、端口、协议，点击**保存**。
4.（可选）在「绕过列表」中加入需要直连的地址，每行一个；点击**保存**。
5. 回到弹窗，在**代理模式**里选择「固定服务器」（代理未启用时这一步只是把它记为待启用模式）。
6. 打开顶部的**启用开关**。此时才真正应用所选模式——状态应显示为已启用，并列出当前端点。
7. 访问网页验证流量是否经由 v2raya。用完后可关闭开关恢复直连。

> 如需使用 PAC：在设置页面选择「远程 URL」或「内联脚本」来源、填入内容并**保存**（仅存储），再回弹窗切换到「PAC」模式并打开开关即可生效。

## 状态与错误提示

- **工具栏指示**：直连状态与 系统 / 固定服务器 / PAC 状态在视觉上有区分；出现未解决的代理错误时也会有区别于其他状态的提示。
- **端点不可达**：在固定服务器模式下，若代理报告错误事件，弹窗会提示当前端点（主机:端口）不可达。
- **配置未应用**：若浏览器拒绝应用某次配置，扩展会保留先前生效的模式，并提示「配置未被应用」以及仍然生效的模式。
- **存储失败**：若持久化失败，会保留之前已存储的配置并提示失败原因。
- **启动恢复异常**：若启动时读取或校验已存储配置失败，扩展会回退到直连模式，并提示已存储配置无效。

---

## 数据持久化

- 配置通过 `chrome.storage` 持久化，浏览器关闭重启后仍然保留。
- 浏览器启动时，扩展会在数秒内**自动恢复**最近一次生效的代理模式；固定服务器模式会一并恢复端点与绕过列表。
- 没有任何已存储配置时，默认回退到**直连**模式。
- **禁用**代理只是切回直连，**不会**删除你已保存的端点 / 绕过列表 / PAC 配置。

---

## 权限说明

`manifest.json` 仅申请两项权限，遵循最小权限原则：

- **`proxy`**：读取和写入浏览器代理设置（这是扩展的核心能力）。
- **`storage`**：持久化你的代理配置。

> 由于 `proxy` 权限会接管浏览器的代理设置，使用时请指向你信任的 v2raya 端点；测试结束后建议在弹窗中关闭开关以恢复直连。

## 常见问题（FAQ）

**Q：加载时提示「无法加载 xxx.html」或路径错误？**
A：请确保运行的是 `npm run package`（而不是只 `npm run build`），并加载 `extension/` 目录而非 `dist/`。`extension/manifest.json` 中的路径已针对组装后的结构修正。

**Q：切换到「固定服务器」被拒绝？**
A：需要先在设置页面保存一个**有效的代理端点**（主机 1–253 字符、端口 1–65535、协议四选一）。同理，切换到「PAC」前需先保存有效的 PAC 来源（远程 URL 或内联脚本）。

**Q：开了代理但访问 LAN/本地服务不通？**
A：把对应地址加入**绕过列表**（默认已包含 `localhost` 和 `127.0.0.1`），让它们直连。

**Q：扩展会自动启动 v2raya 吗？**
A：不会。扩展只配置浏览器代理，v2raya 需要你自行在 LAN 内部署并保持运行。

**Q：关闭代理后我的配置会丢吗？**
A：不会。禁用只是切回直连，已保存的端点 / 绕过列表 / PAC 都会保留，下次启用即可恢复。
